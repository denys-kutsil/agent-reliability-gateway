# AWS і CDK простими словами

Нотатка для себе: що ми зробили в ARG-02 (AGE-14) і навіщо. Без складних термінів.

## Велика картина

Проєкт працюватиме в AWS. AWS це склад, де можна орендувати «полиці»: бази даних, черги, маленькі програми (Lambda). Платиш за те, що орендуєш. Наша мета: користуватися справжнім AWS, але платити $0.

Щоб не платити випадково, потрібні три речі:

1. Не працювати під root (головним акаунтом).
2. Мати бюджет-сигналізацію.
3. Описувати все кодом, щоб однією командою усе видалити.

## 1. Хто заходить в AWS

- **Root** це власник акаунта. Може все, зокрема видалити акаунт. Тому ним не працюють. Він потрібен лише для налаштувань акаунта.
- **Користувач `developer`** (роль `DeveloperAdmin`) це наш робочий вхід. Створений через IAM Identity Center. Його ключі короткоживучі й спливають, тоді треба знову увійти.
- **Профіль CLI `my-project`** це збережений вхід для командного рядка. Команди запускаємо так: `AWS_PROFILE=my-project ...`.
- **Профіль `default`** навмисно не залогінений. Якщо забути вказати профіль, команда просто впаде, а не піде від root.

Перевірити, хто ти зараз: `AWS_PROFILE=my-project aws sts get-caller-identity`. У відповіді не має бути `:root`.

## 2. Бюджет-сигналізація

«My Zero-Spend Budget» з лімітом $1 надсилає лист, якщо з'являються витрати. Це захист від випадкових грошей. Перевір у консолі (Billing, Budgets), що лист іде на твою пошту.

## 3. CDK: інфраструктура кодом

Замість клацання мишкою в консолі пишемо список «що хочу» у TypeScript (`packages/infra`).

- `pnpm deploy:aws` створює все з цього списку в AWS.
- `pnpm destroy:aws` видаляє все з цього списку.

Список називається **стек** (`ArgStack`). Зараз він порожній. Далі в нього додаватимуться таблиці DynamoDB, черга SQS, Lambda.

Файли:

| Файл                                    | Для чого                                       |
| --------------------------------------- | ---------------------------------------------- |
| `packages/infra/lib/arg-stack.ts`       | Сам стек (список замовлень).                   |
| `packages/infra/bin/app.ts`             | Точка входу: для якого акаунта і регіону стек. |
| `packages/infra/cdk.json`               | Як CDK запускає цей застосунок.                |
| `packages/infra/test/arg-stack.test.ts` | Тест: у стеку не має бути платних ресурсів.    |

## 4. Bootstrap: одноразова підготовка

Перед першим деплоєм CDK має мати «службову кімнату» в акаунті. Команда `cdk bootstrap` створила її один раз:

- S3-бакет, куди CDK кладе файли для деплою;
- IAM-ролі, під якими CDK створює ресурси;
- ECR-репозиторій для образів;
- параметр із версією bootstrap.

Це безкоштовно. Ці ресурси лишаються після `destroy`, бо потрібні для наступних деплоїв. Стек у консолі AWS називається `CDKToolkit`.

## 5. Що ми перевірили

1. `cdk deploy` створив порожній `ArgStack` (≈25 с).
2. `cdk destroy` видалив його. Після цього AWS каже, що стека немає.

Тобто повний цикл «створити і прибрати» працює. Далі просто додаємо в стек ресурси.

## Правила $0 (з CLAUDE.md)

Не використовуємо те, що коштує грошей одразу: NAT Gateway, RDS, балансувальник (ALB), ECS/Fargate, EKS, MSK, Secrets Manager, публічні IPv4, власні KMS-ключі. Lambda не кладемо у VPC. Тест у `arg-stack.test.ts` перевіряє частину цього автоматично.

## Пастки, на які ми вже наступили

- `pnpm setup` і `pnpm deploy` це вбудовані команди pnpm, вони не запускають наші скрипти. Тому: `pnpm run setup`, а для AWS `pnpm deploy:aws`.
- Під root не працюємо. Профіль `default` навмисно вимкнений.

## Швидка шпаргалка

```
AWS_PROFILE=my-project aws sts get-caller-identity   # хто я зараз
AWS_PROFILE=my-project pnpm deploy:aws               # створити стек
AWS_PROFILE=my-project pnpm destroy:aws              # видалити стек
AWS_PROFILE=my-project pnpm --filter @arg/infra synth  # лише згенерувати шаблон, нічого не створюючи
```
