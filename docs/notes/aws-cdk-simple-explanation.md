# Проєкт, AWS і CDK простими словами

Нотатка для себе. Тут зібрано все, що потрібно, щоб не губитися: що це за проєкт, як влаштований репозиторій, які є команди, які сервіси AWS використовуються, де лежать креденшіали і що зараз розгорнуто.

Оновлюй цей файл, коли додається щось нове. Остання велика зміна: задача ARG-03 (mock-провайдери на Lambda).

---

## 1. Проєкт у двох реченнях

AI-агент викликає зовнішні HTTP API (календар, пошта, CRM), які можуть збоїти: відповідати 429 чи 503, зависати, або виконати дію, але загубити відповідь. **Гейтвей** стоїть між агентом і цими API й гарантує, що дія виконається один раз і безпечно, а експеримент міряє різницю в цифрах: з гейтвеєм і без нього.

Зараз ми на самому початку: будуємо «поле бою» (фальшиві API, які будемо ламати). Сам гейтвей ще не написаний.

## 2. Навіщо AWS і як не платити

Мета: практикуватись зі справжнім AWS, але платити **$0**. Для цього:

1. **Не працюємо під root** (головний акаунт, може все). Тільки під роллю `DeveloperAdmin`.
2. **Є бюджет-сигналізація** («My Zero-Spend Budget», $1), яка надсилає лист, якщо з'являються витрати.
3. **Усе описано кодом (CDK)**, тому одна команда створює, а друга видаляє. Забутих ресурсів не буде.
4. **Заборонені платні сервіси**: NAT Gateway, RDS, ALB, ECS/Fargate, EKS, MSK, Secrets Manager, публічні IPv4, власні KMS-ключі. Lambda не кладемо у VPC. Тест у `packages/infra/test/arg-stack.test.ts` падає, якщо хтось додасть такий ресурс.

│   ├── config.mjs             спільні налаштування локального режиму
│   └── smoke-aws.sh           перевірка розгорнутого в AWS (підписаний запит)
├── docs/

    ├── providers-mock/        три фальшиві API (Calendar, Email, CRM)

Пакети, які ще не існують, але заплановані: `adapters-aws`, `gateway-mcp`, `control-plane` (NestJS, лише бекенд), `llm`, `rag`, `worker`, `agent`.

### Що в кожному пакеті

**`packages/providers-mock`**: три фальшиві сервіси. Кожен навмисно різний, щоб гейтвей не залежав від формату одного API.

| Файл                   | Що робить                                                                                 |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| `calendar.ts`          | REST JSON. Створити подію, знайти за `clientRef`, прочитати за id                         |
| `email.ts`             | Form-encoded. Має свій `Idempotency-Key`: повтор із тим самим ключем не шле другого листа |
| `crm.ts`               | JSON-RPC-подібний. Усі відповіді 200, помилки в тілі. Пошуку немає навмисно               |
| `http.ts`              | Формат запиту і відповіді, не залежить від Node чи Lambda                                 |
| `state.ts`             | «Записна книжка»: куди провайдери пишуть створене. Порт плюс версія в пам'яті             |
| `dynamodb-state.ts`    | Та сама книжка, але в DynamoDB (таблиця стану)                                            |
| `router.ts`            | Один вхід: `/calendar/*`, `/email/*`, `/crm/*`                                            |
| `server.ts`, `main.ts` | Локальний HTTP-сервер (`pnpm mock`)                                                       |
| `lambda.ts`            | Обгортка для AWS Lambda: приймає подію від AWS і передає тому ж коду                      |
| `deps.ts`              | Залежності: книжка, генератор id, годинник (у тестах підміняються)                        |

**`packages/infra`**: інфраструктура кодом (CDK).

| Файл                     | Що робить                                                           |
| ------------------------ | ------------------------------------------------------------------- |
| `bin/app.ts`             | Точка входу: для якого акаунта й регіону будувати                   |
| `lib/arg-stack.ts`       | Головний «список замовлень» (стек `ArgStack`)                       |
| `lib/mock-providers.ts`  | Що саме створити для mock-провайдерів: таблиця, Lambda, адреса      |
| `cdk.json`               | Як CDK запускає цей застосунок                                      |
| `test/arg-stack.test.ts` | Тести: немає платних ресурсів, адреса вимагає підпису, права вузькі |

### Чому в імпортах `.js`, хоча файли `.ts`

Налаштування TypeScript `NodeNext` вимагає писати розширення того файлу, який існуватиме після компіляції. TypeScript сам знаходить відповідний `.ts`. Це відома дивність, у цьому проєкті вона обов'язкова.

## 4. Усі команди

Команди запускаються з кореня репозиторію.

### Перевірки (обов'язкові перед завершенням будь-якої задачі)

| Команда          | Що робить                                 | Docker | AWS |
| ---------------- | ----------------------------------------- | ------ | --- |
| `pnpm lint`      | ESLint і перевірка форматування Prettier  | ні     | ні  |
| `pnpm typecheck` | Перевірка типів TypeScript у всіх пакетах | ні     | ні  |
| `pnpm test`      | Усі тести (Vitest)                        | ні\*   | ні  |

\* Тести DynamoDB проти DynamoDB Local **пропускаються автоматично**, якщо Docker не запущений. З Docker вони виконуються.

### Локальний режим (без акаунта AWS)

| Команда                      | Що робить                                                                                                |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| `pnpm run setup`             | Ставить залежності, підіймає Docker, створює таблиці DynamoDB і схему Postgres. Можна запускати повторно |
| `pnpm run doctor`            | Перевіряє Node, Docker, порти 5432 і 8000 і каже, що виправити                                           |
| `pnpm mock`                  | Фальшиві API на `http://127.0.0.1:8081`, стан у пам'яті                                                  |
| `pnpm mock --state=dynamodb` | Те саме, але стан у DynamoDB Local (потрібен `pnpm run setup`)                                           |

Приклад, що спробувати руками після `pnpm mock`:

```
curl -X POST localhost:8081/calendar/events -H 'content-type: application/json' \
  -d '{"title":"Standup","start":"2026-03-01T10:00:00Z","end":"2026-03-01T10:15:00Z","clientRef":"demo-1"}'
curl "localhost:8081/calendar/events?clientRef=demo-1"
```

**Пастка:** завжди пиши `pnpm run setup` і `pnpm run doctor`. Просто `pnpm setup` і `pnpm doctor` це вбудовані команди pnpm, які роблять зовсім інше (`pnpm setup` змінює профіль оболонки).

### AWS (справжній акаунт)

Усі команди виконуються з профілем: `AWS_PROFILE=my-project ...`.

| Команда                                  | Що робить                                                                   | Що змінює в AWS            |
| ---------------------------------------- | --------------------------------------------------------------------------- | -------------------------- |
| `aws sso login --profile my-project`     | Вхід. Токен спливає за кілька годин, тоді треба знову                       | нічого                     |
| `aws sts get-caller-identity`            | Показує, хто ти зараз. Має бути `DeveloperAdmin`, не `:root`                | нічого                     |
| `pnpm --filter @arg/infra synth`         | Генерує шаблон CloudFormation локально                                      | нічого                     |
| `pnpm --filter @arg/infra exec cdk diff` | Показує, що зміниться при деплої                                            | нічого                     |
| `pnpm deploy:aws`                        | Створює ресурси зі стека (`cdk deploy`)                                     | **створює ресурси**        |
| `pnpm smoke:aws`                         | Перевіряє розгорнуте: без підпису 403, з підписом створює й знаходить подію | створює одну тестову подію |
| `pnpm destroy:aws`                       | Видаляє ресурси стека (`cdk destroy`)                                       | **видаляє ресурси**        |

Що вкладено в `pnpm deploy:aws`:

```
pnpm deploy:aws
 └─ pnpm --filter @arg/infra run deploy
     └─ cdk deploy --require-approval never
         ├─ tsx bin/app.ts                 будує список ресурсів
         ├─ esbuild ... lambda.ts          пакує код Lambda в один файл
         └─ завантаження пакета і CloudFormation   створює ресурси
```

**Увага:** прапорець `--require-approval never` вимикає запит підтвердження перед змінами прав доступу (IAM). Якщо хочеш щоразу бачити такі зміни, запускай `cdk deploy` без нього або спершу роби `cdk diff`.

**Пастка:** `pnpm deploy` це теж вбудована команда pnpm. Тому скрипти викликають `pnpm --filter @arg/infra run deploy`, а ти використовуй `pnpm deploy:aws`.

## 5. Сервіси AWS, які ми використовуємо

### Зараз розгорнуто (стек `ArgStack`)

| Сервіс                  | Що це простими словами                                       | Навіщо тут                                                                                                                          |
| ----------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| **CloudFormation**      | «Виконавець замовлень»: бере шаблон і створює ресурси        | CDK перетворює наш код на шаблон, CloudFormation його виконує. Один стек це один пакет ресурсів, що створюється і видаляється разом |
| **Lambda**              | Маленька програма, що запускається тільки коли її викликають | Хостить усі три фальшиві API. Поза VPC, Node 22, arm64, 256 МБ, ліміт 10 с                                                          |
| **Lambda Function URL** | Готова HTTPS-адреса для функції                              | Вхід у Lambda. З типом `AWS_IAM`: запит мусить бути підписаний (SigV4), інакше 403                                                  |
| **DynamoDB**            | База даних «ключ-значення», безсерверна                      | Тут зберігає все, що створили mock-провайдери. On-demand: платиш за запити, у free tier це копійки                                  |
| **IAM (роль Lambda)**   | Набір прав: що кому дозволено                                | Lambda може лише `GetItem`, `PutItem`, `UpdateItem`, `ConditionCheckItem` і лише на свою таблицю                                    |
| **CloudWatch Logs**     | Сховище логів                                                | Логи Lambda, зберігаються тиждень                                                                                                   |

### Створено один раз для всього акаунта (`cdk bootstrap`, стек `CDKToolkit`)

| Ресурс             | Навіщо                                               |
| ------------------ | ---------------------------------------------------- |
| S3-бакет (staging) | CDK кладе сюди пакети Lambda і шаблони перед деплоєм |
| ECR-репозиторій    | Для образів, які ми поки не використовуємо           |
| IAM-ролі (кілька)  | Під ними CDK створює ресурси                         |
| SSM-параметр       | Версія bootstrap                                     |

Ці ресурси безкоштовні й **лишаються після `destroy`**: вони потрібні для наступних деплоїв. `pnpm destroy:aws` видаляє тільки `ArgStack`.

### Налаштування акаунта (поза кодом)

| Сервіс                  | Навіщо                                                                |
| ----------------------- | --------------------------------------------------------------------- |
| **IAM Identity Center** | Дає вхід ролі `DeveloperAdmin` через браузер, із тимчасовими токенами |
| **AWS Budgets**         | «My Zero-Spend Budget»: лист, якщо з'являються витрати                |

### Заплановано на пізніші задачі

| Сервіс                  | Для чого                                                 |
| ----------------------- | -------------------------------------------------------- |
| **SQS і DLQ**           | Черга для довгих викликів і черга для «зламаних» завдань |
| **Lambda worker**       | Обробляє чергу, викликає API                             |
| **S3**                  | Audit-журнал (JSONL)                                     |
| **EventBridge**         | Події для підписників                                    |
| **SSM Parameter Store** | Ключі LLM (безкоштовно, на відміну від Secrets Manager)  |
| **API Gateway**         | Пізніше, для HTTP-входу з лімітами й авторизацією        |

**Чого в AWS не буде:** PostgreSQL. Він лише в Docker локально, бо RDS платний.

## 6. Як іде запит

### Локально

```
curl ──► Node HTTP-сервер (8081) ──► router ──► Calendar / Email / CRM ──► книжка стану
                                                                              (пам'ять або DynamoDB Local)
```

### В AWS

```
твій запит ──(підпис SigV4)──► Function URL ──► Lambda ──► router ──► Calendar / Email / CRM ──► DynamoDB
                               (AWS_IAM)        lambda.ts            той самий код, що й локально
```

Код провайдерів один. Відрізняється лише «обгортка» навколо нього (`server.ts` локально, `lambda.ts` у хмарі) і місце зберігання стану.

## 7. Креденшіали: де які мають бути

| Де                                | Який ключ                                 | Де лежить                                                                        |
| --------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------- |
| Локально (Docker, DynamoDB Local) | Вигаданий `local` / `local`, не справжній | У коді (`setup.mjs`, `dynamodb-state.ts`). Нічого не відкриває                   |
| Твій комп'ютер → справжній AWS    | Тимчасовий токен SSO профілю `my-project` | `~/.aws/config` і `~/.aws/sso/cache`, поза репозиторієм. Спливає за кілька годин |
| Lambda у хмарі                    | Ніяких ключів: IAM-роль, яку створив CDK  | AWS підставляє сам                                                               |
| Ключі LLM (пізніше)               | Посилання на параметр SSM                 | Значення тільки в AWS, у коді лише посилання                                     |

Правила:

- Постійних ключів доступу AWS немає ніде. Тому витекти нічому.
- Профіль `default` навмисно вилогінений, щоб випадково не працювати під root.
- У репозиторій не потрапляє нічого секретного. `.env` у `.gitignore`.
- Помилка `Token has expired` означає лише, що SSO-сесія протухла: виконай `aws sso login --profile my-project`.

## 8. Життєвий цикл AWS-частини

1. **Один раз:** `cdk bootstrap` готує акаунт (вже зроблено).
2. **Змінив код інфраструктури:** `cdk diff` показує зміни, `pnpm deploy:aws` застосовує.
3. **Перевірка:** `pnpm smoke:aws`.
4. **Закінчив працювати:** `pnpm destroy:aws` прибирає стек. Таблиця не має захисту від видалення, тож дані тестів зникнуть.

## 9. Що зараз розгорнуто в акаунті

- `CDKToolkit` (bootstrap): безкоштовний, лишається.
- `ArgStack`: Lambda, Function URL, таблиця стану, логи. У free tier. Видаляється через `pnpm destroy:aws`.

Перевірити, що є: консоль AWS, регіон **us-east-1**, сервіс CloudFormation, стеки `CDKToolkit` і `ArgStack`.

## 10. Словник

- **CDK**: інструмент, щоб описувати ресурси AWS кодом на TypeScript.
- **Стек**: пакет ресурсів, що створюється й видаляється разом.
- **Bootstrap**: одноразова підготовка акаунта до CDK.
- **Synth**: згенерувати шаблон, нічого не створюючи.
- **Lambda**: функція, що запускається за запитом, без постійно працюючого сервера.
- **Function URL**: адреса, за якою можна викликати Lambda по HTTPS.
- **SigV4**: спосіб підписати запит ключами AWS, щоб довести, що ти це ти.
- **IAM**: система прав доступу AWS. **Роль**: набір прав, який можна «надіти».
- **SSO**: вхід через браузер із тимчасовими токенами, без постійних ключів.
- **DynamoDB**: база даних «ключ-значення». **DynamoDB Local**: її копія в Docker для локальної роботи.
- **clientRef**: мітка, яку клієнт вигадує для створеної сутності, щоб потім перевірити, чи вона вже існує.
- **Idempotency-Key**: заголовок, за яким API розуміє, що це повтор того самого запиту, і не робить дію вдруге.
- **Reconcile**: після збою перевірити, чи дія вже виконана, замість наосліп повторювати.
- **Порт і адаптер**: у коді логіка говорить із «портом» (інтерфейсом), а за ним стоїть змінний «адаптер» (пам'ять, DynamoDB Local, справжній DynamoDB).
